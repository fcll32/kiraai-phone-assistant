# 手机和 Kira 管理网页共用公网 5267

手机填 `公网IP:5267`；浏览器打开 `https://公网IP:5267`。App 的密码、校验码和自动补全路径继续有效。

## Docker 部署

1. 先通过原管理网页安装插件，开启“共用 HTTPS/WSS 入口”，公网端口 5267、内部端口 8443，保存并启动。
2. 在原来的 Docker Compose 文件中替换端口映射，其他设置和数据目录保留：

   ```yaml
   ports:
     - "5267:8443"
     - "127.0.0.1:15267:5267"
   ```

3. 重新创建容器，安全组放行 TCP 5267。浏览器改用 HTTPS，手机改填公网 IP:5267。

不要同时保留原来的 `5267:5267`，它会与新映射抢占主机端口。内部 8443 只接收 Docker 转发，无需单独映射成公网 8443。

第二条映射是备用管理入口，只允许服务器本机访问。需要修复设置时，可在自己的电脑运行：

```text
ssh -L 15267:127.0.0.1:15267 你的用户名@你的服务器IP
```

保持 SSH 连接，浏览器打开 `http://127.0.0.1:15267`。如果电脑上的 15267 被占用，修改命令第一个端口和浏览器地址即可。

## 直接运行 Kira，没有 Docker

共用入口和 Kira 的内部网页服务仍需使用不同的监听端口：

- 在 Kira 的数据目录 `webui.json` 中，将网页 `host` 设为 `127.0.0.1`、`port` 设为 `15267`；保留其他字段和原登录信息。
- 插件中开启共用入口，`public_port` 和 `phone_port` 都设为 `5267`。原来的 `public_ip`、密码和授权聊天保持自己的设置。
- 重启 Kira，通过服务器本机的 `http://127.0.0.1:15267` 登录并首次启动共享入口。远程服务器可用上面的 SSH 转发。
- 对外仍使用 `https://公网IP:5267`；安全组只放行 5267。

## 运行行为

共享入口仅转发到本机 Kira，目标端口读取 `webui.json`，默认 5267。网页原来的登录验证、Cookie、上传限制和 WebSocket 权限继续由 Kira 处理；关闭网页登录验证时，插件拒绝启动共享入口。

手机控制和通话仍使用独立密码，停止手机服务会断开它们。共享管理入口在第一次启动后保留，插件重载或 Kira 重启后仍可用于重新启动手机服务。公网 IP 或内部监听端口变化，需要重启 Kira。

自签名证书首次在浏览器访问时可能提示不受信任，需要由使用者核对并处理证书信任；可改用带可信证书的外部反向代理。App 使用管理页提供的证书校验码，无需关闭证书校验。
