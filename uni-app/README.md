# 手机 App 使用说明

1.0.1 使用 uni-app x，支持 Android 8 起。安装发行包中的 APK 即可。详细配对见根目录「新手使用说明.md」。

## 界面风格

界面参考 [Auroraqua UI](https://gitee.com/micromimo/Auroraqua-UI) 的冰态果冻、悬浮玻璃与柔和高光，按本项目的连接、通话和更新功能重新实现；没有引入其 React 运行时、字体或组件代码。设备、连接、通话、说明、关于和菜单各有同角色的场景背景，分别展示手机、认真接线、闭眼倾听、托腮看书、眨眼创作和挥手迎接。原图保留在首次欢迎页。所有图片随 APK 本地打包，叠加蓝色柔光，离线可用。

页面上方为人物和短标题留出固定区域，功能卡片在下方独立滚动；手机和能力图标缩小，避免遮住正脸。菜单五个入口与底部三项导航使用对应功能的 Q 版动作：点手机、接连接线、戴耳麦说话、翻指南和调整设置。底栏继续保留液滴胶囊拉伸、图标先缩后弹和文字渐变；图片路径不随选中状态更换，避免切换时重新加载表情。

菜单下方六项状态会根据实际连接、通话、无障碍、防截屏、动效和实验状态换表情与文字；连接中不算连接成功，状态格本身不会开启功能。九张透明表情和六张场景的用途、生成提示词见 `static/companions/README.md` 和 `static/scenes/README.md`。

首页、连接表单、通话、抽屉、关于、首次引导与插件管理页采用统一的蓝色层次。翻卡、叠卡、液滴导航、聚光引导、按钮完成反馈和调速功能继续保留。模糊只用于停稳的主卡、底栏和弹窗；滚动卡片用半透明底色，旧版 Android 使用雾面底。

## 连接与通话

在 KiraAI 安装插件 ZIP，打开「手机连接」，填公网 IP 和允许使用的聊天。App 底部点「连接」，复制服务器地址、密码和校验码；地址只需 `公网IP:端口`。开启无障碍服务后回到「设备」，点开始连接。草稿会保留，连接时先检查并保存输入；必须在确认弹窗中同意才启动。未就绪时查看按钮下方的提示。

「通话」页由你主动授权麦克风并开始通话；授权成功后需再次点击。服务器需配置默认聊天、语音识别和合成模型。虚拟麦克风仍是独立兼容性实验，不代表 QQ／微信通话可用。

背景改为低饱和灰蓝，卡片使用雾白，按钮和选中状态延续蓝色。首页文字与手机图案左右排列，缩短标题并统一行距；翻面、叠卡、滑动、弹窗、完成反馈和调速仍保留。

玻璃质感用于连接主卡、菜单按钮、连接状态、底部导航和底部弹窗。背景只用大块灰蓝与淡青色，文字保留深色；表面叠加 10% 白色、1px 亮边和细微弧形边线，主卡与导航使用很淡的阴影。Android 12 起使用固定 10px 背景模糊；Android 8–11 使用更实的雾面底色。翻卡、导航切换及拖动弹窗期间暂停对应模糊，停稳后恢复，不对模糊半径做动画。网页预览另加轻微提饱和，不代表手机支持同样的滤镜组合。

## 界面操作

- 首页连接卡：左滑超过 44px 或轻点翻面行查看概览，右滑返回；滑到边界会回弹并提示。翻面不会开始连接，下方按钮始终保留。
- 主卡标题、说明和服务器地址分别过渡，只有变化的那一行滑出并换入新文字。概览中的虚线加号可进入连接设置、无障碍设置或检查连接准备。
- 底部三项：设备、连接、通话。胶囊随选择拉伸、回弹；内容按方向轻推入。菜单的“关于”集中放 GitHub 项目链接、应用更新、动效开关和速度，原来的“界面偏好”入口已合并。
- 底栏只保留设备、连接、通话三项，均匀占满宽度；不再显示独立的「＋ 向导」按钮。
- 连接步骤可点标签或左右滑卡，松手按惯性吸附。当前卡片按压微倾、回弹后展开详情。
- 详情页头图视差、大标题吸顶；中间状态松手后自动展开或收起。点关闭返回。
- 设备页的手机能力卡可翻面；背面稳定后显示帮助和连接入口。
- 关于页的动画速度面板升起时，背景缩小并变暗；顶部可上下拖，向下超过三分之一或快速甩动关闭。滚轮与顶部拖动区域分开，取消不保存草稿。
- 输入框用浮动名称代替占位文字，填写后名称保留在上方。
- 首次启动弹出三页欢迎介绍，可左右滑动或跳过；结束后用聚光灯说明连接入口、开始按钮和连接状态。显示前就记录已展示，中途退出、尚未连接或再次打开都不会自动重播；旧版已经看过或已配置的用户也不重播。首页和使用说明不再放重播按钮，连接步骤仍可在使用说明查看。
- 地址、密码或校验码格式有误时，输入框轻摇并显示具体原因；重新输入即清除红色。密码错误后会选中内容，方便重输。
- 密码下方的四格强度条只在本机估计好不好猜，不代表服务器已验证；手机密码必须与服务器一致。
- 防截屏开关在侧边菜单底部，新安装默认关闭；已有保存的选择会继续保留。原生确认成功后才显示绿色，失败保留原状态。
- 保存、连接成功才显示完成勾号。动画速度可调，也可关闭各类动效，不改变实际连接或 AI 速度。

Android 8–10 仅提供控件信息和操作，11+ 可按需截图；不持续录屏。

## 安装提示

桌面图标使用新生成的拿手机角色头像，原图在 `android-app/app/src/main/res/drawable-nodpi/kira_launcher_art.png`，由原生共享资源引用。安全内边距用于避免圆形桌面图标裁掉正脸，普通图标和圆形图标使用同一套资源；完整生成记录见 `phone_control/web/assets/avatar-prompts.json`。

应用内更新入口在侧边菜单的「关于」→「应用更新」。每次回到 App 时会尝试静默检查，同一进程内最多每六小时检查一次；已有新版信息、正在下载或待安装时跳过。发现新版后，菜单按钮和「关于」条目显示红点，安装新版本后消失；网络失败不弹窗，仍可手动检查。自动检查只获取版本信息，不下载或安装。

手动检查后，可先看说明再下载；显示真实进度，也可以取消。下载交给 Android 后台继续，回到页面会恢复状态。下载和校验完成后点「安装更新」，第一次按系统提示允许本 App 安装应用，再返回点一次安装。安装前先停止手机控制、通话和实验，系统最终仍会请你确认。

更新只读取本项目 GitHub 的正式发布，不使用手机连接密码。文件会校验完整性、应用名称对应的安装身份、版本码及签名；出错不会覆盖安装。当前是 1.0.1/code 2，可覆盖安装同签名的 1.0.0/code 1。正式发布后，旧版可在关于页检查更新。

Web 只是界面预览，不能连接手机或采集麦克风。

手机如提示版本过低或签名不一致，先保存连接信息，再卸载旧 App、安装并重新填写；卸载会清除手机里的设置。

## 以后如何发布新版

1. 在根目录 `release.json` 更新显示版本和内部版本码，例如 `1.0.2`、`3`，运行 `python scripts/sync_release.py --write`。内部版本码每次必须增加；不要一直用 1。
2. 编译 APK，并始终使用之前的同一签名文件签名。CI 临时调试签名不能覆盖这里的发行包。
3. 运行 `python scripts/package_release.py --apk 已签名的.apk`，得到 APK、源码和 `SHA256SUMS.txt`。
4. 在当前 GitHub 仓库创建正式 Release，例如标签 `v1.0.2`，上传同一批 APK 和校验文件，填写更新说明。保留生成的 APK 文件名；草稿和预发布不会推送给普通用户。

更新仓库在 `release.json` 的 `repository` 中指定，发布脚本会同步到 App。GitHub 访问不顺时可以稍后重试。
